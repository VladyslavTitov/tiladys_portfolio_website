**Subsequent authorized actions:** [Approved recovery results](approved-recovery-results.md) record the completed public-only rollback and exact-token revocation. ## 1. Confirmed root causes

**Production: incompatible public application and database versions.** `https://tiladys.com/en/portfolio` serves deployment `dpl_R2D4fuBc7MKSpc3CCqjuho1xjrmz`, commit `141b2edd8f51597a90d9727241fad29a0cf45e83`. The build is **READY**, target **production**, but its database has only the first 13 of the required 23 migrations. Read permissions and connectivity work. Runtime logs explicitly identify Prisma **P2022**, missing `ProjectImage.archivedAt`, on `/en/portfolio/donetsfit`. Portfolio catches the database failure and returns the generic unavailable state with HTTP **200**; a status-only health check misses the incident.

`apps/web/lib/public-projects-db.ts` filters related images with `archivedAt: null` for both cards and details; `apps/web/app/api/public/media/[id]/route.ts` requires the same field. The field arrives in `20261014010000_editor_retention`, which is absent in Production. `apps/web/app/[locale]/portfolio/page.tsx` logs only `[PUBLIC_PORTFOLIO_UNAVAILABLE]`, without sending exception details to visitors. No fabricated projects or fallback database records were introduced.

**Preview: no administrator exists, plus an origin configuration problem on the branch alias.** A single synthetic login on the immutable Ready deployment returned **401 `{"error":"Invalid"}`**, consistent with zero AdminUser rows. The same synthetic request on its assigned recovery branch alias returned **403 `{"error":"Invalid origin"}`**. Both statuses appear in deployment logs. The login UI maps both failures to “Login failed or temporarily locked.” Creating an administrator alone will not repair alias-origin rejection.
