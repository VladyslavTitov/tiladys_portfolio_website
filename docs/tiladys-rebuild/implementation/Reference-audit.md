## Requirements that change implementation

- Reconcile the deployed feature/services-redesign baseline identified by the analysis (e82bff04aac9915585b10cc853fe31c558a5964b), current checkout and Node 24 configuration. Older main lacks important CRM/invoice schema. Existing schema evidence is not proof that a deployment points to that database; inspect only non-secret environment mapping.
- Preserve existing IDs, financial records, translations, issued PDF bytes/checksum, slug aliases, partial one-active-draft-per-job index, atomic numbering and invoice row locks. Customer is still the database entity even when UI says Client. Do additive evolution; no production reset, renumbering, guessed tax backfill or identity migration.
- New draft previews and new issuances use complete DE section followed by complete EN section, a single invoice identifier and amounts. Long DE can occupy several pages; EN starts on a fresh page. Old issued bytes remain identical. Issued PDF missing means operator-recovery conflict, never regenerate from mutable current data. Generic serviceName is not proof of EN; explicit reviewed DE/EN counterparts must satisfy issuance.
- Tax mode remains UNCONFIRMED until actual owner-confirmed settings satisfy issuance. Legal/tax wording, actual bank details, processors/retention, structured e-invoice needs and model/storage capability are launch facts, never mockup values. A bilingual ordinary PDF does not establish structured e-invoicing compliance.
- Source photos allow 5 × 1024 × 1024 bytes each and 15 × 1024 × 1024 aggregate, independently checked before and after storage. The proposed count cap is 10; JPEG/PNG/WebP first. Preserve bounded signature/decode/dimension/pixel/resource checks. 5MiB source cannot fit a function's 4.5MB request limit; reserve, direct-upload private quarantine, process and finalize metadata instead. Bounded HEIC conversion or a specific recovery error is required. Do not silently send without failed photos.
- Model upload is separately gated: proposed private STL 25MiB each, 50MiB sum, max 3; no G-code/archives or printer execution. No-file idea enquiries stay valid. Enable only with resource, storage, validation and association protections.
- Original Unicode enquiry text/newlines/emoji is immutable, safely rendered and independent of UI/reply locale. Persist one enquiry per idempotency key; acknowledgement mail failure reports saved status. SMTP accepted-but-record-failed is uncertain and reconciled, never blindly resent. Opening a message may mark READ, never REPLIED.
- Leads may have incomplete billing data. Shared family/company email is valid: duplicate suggestions require human review and do not auto-merge; email is not globally unique. Validate customer/company/job/file associations on server and stale revisions on every save.
- Preserve ServiceJobStatus PLANNED, IN_PROGRESS, WAITING_CUSTOMER, COMPLETED, CANCELLED. Print stage/readiness and quote acceptance are separate records/states. Job completion creates neither an invoice nor a public project; conversion to reviewed drafts is explicit.
- Invoice DRAFT/ISSUED/CANCELLED is distinct from derived UNPAID/PARTIAL/PAID and overdue. Positive payments cannot exceed locked current balance; retries return the same ledger record. Corrections preserve original invoice and payment history, require reviewed balance treatment and append history. Preview never allocates a legal invoice number.
- Catalogue prices need decimal strings/structured modes; FROM/PERCENTAGE require explicit agreed amounts and MONTHLY a valid ordered period. Keep historical labels/snapshots when deactivating. HALF_UP server totals and atomic Europe/Berlin business-year sequences remain authoritative. No JS float money, SELECT MAX+1 or raw display-string invoicing.
- Quote revisions are frozen when sent; acceptance records exact current revision, evidence/date/source. Old/expired acceptance requires review/renewal; job/invoice conversion is idempotent and explicit. The existing direct job-to-invoice path must continue without quote prerequisites.
- Public projection serves only published Project/Product/Review fields and approved media derivatives. Private files remain private after job completion. Check status even for resized media, invalidate list/detail/media/sitemap after withdrawal, and preserve one-hop canonical slug aliases. Preview routes are authenticated and non-indexable.
- Keep custom Argon2/hashed opaque sessions and existing secret phrase; the phrase is not MFA. Managed neon_auth tables are not authorization to migrate identity or add public owner sign-up. Login throttling needs shared counters, session changes reauthentication/audit and cookie mutations exact allowed Origin.
- The live footer stays five-column Brand/Contact/Links/Connect/Legal with original vector marks and gradient, its own responsive progression and centered copyright. Use contact@tiladys.com, +49 163 7235608, Kronenstraße 19, 45479 Mülheim an der Ruhr and verified social destinations. Generated single-row footer is superseded.
- Keep en/de/uk/ru/sk/fr canonical routes (Ukrainian uk), equivalent-page switching, truthful translation availability and reciprocal hreflang only for available published equivalents. Preserve /services, /services/pc-laptop, /services/business-it and legacy /prices intent. No duplicate indexable English fallback or query-filter pages.
- Empty list, no matches, authorization loss and dependency outage are separate states. Errors preserve user input. Success reports persisted fact; uncertain financial/send states require reconciliation. Details preserve Back/focus; mobile menu is below header, independently scrolls, closes on Escape/navigation and prevents scroll bleed.
- Native CSS/SVG/HTML handles surfaces, icons, text, charts, measurements and PDF previews. Generated scenes are illustrations only, never founder identity, real project evidence, actual stock or matching downloadable geometry. Real media missing means honest unavailable/empty state.

## Shared control contract

Every control below inherits visible accessible name, semantic role, keyboard behavior, announced status/errors, non-color-only state, visible focus, >=44px touch area and mobile safe areas/Back navigation. Public controls get published-only reads or bounded submits and no admin credential; private controls recheck owner session and all entity relationships server-side. GET cannot issue, pay, send, merge or publish. Issued/accepted immutable data is locked, with the reason visible. No blanket disabling of an empty-list screen.

Links preserve active-route state and layout during navigation; unavailable actions are omitted or explicitly explained. Filters/tabs use bounded queries, 200–300ms search debounce, cancel stale reads, reset cursor on changed filters and retain shareable URL/browser Back state. Action progress suppresses repeated clicks using the same idempotency key. Fields retain editable input until save requires locking, display inline aria-describedby errors and report saved only after enclosing persistence.

Recovery distinguishes 400/422 fields, 401 expired/missing session, 403 permission/origin, 404 unavailable, 409 stale/conflict, 413 size, 415 type, 429 Retry-After and 503 dependency failure. Inputs and known receipts survive retry; uncertain sends/financial writes are reconciled before retry. Unexpected errors expose only a non-sensitive request reference. Confirmation is for consequential operations recorded below, never routine navigation/filter/draft editing; server enforcement remains independent of any modal.
