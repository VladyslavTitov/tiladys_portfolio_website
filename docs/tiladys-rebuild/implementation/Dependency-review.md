# Dependency review — 14 October 2026

The existing Next 16.3.8, React 19.1.1, Prisma 6.19.3, custom authentication and npm lockfile were retained. Verification used Node 24.21.0; the host also has Node 22.23.1. No framework/auth/database migration was introduced for the redesign.

Sharp was updated from 0.34.5 to **0.35.5** in both applications and as an explicit root development dependency, with a root override. The lockfile version changes were checked: they affect Sharp and its `@img` decoder/platform packages. The root declaration supports the image-processing test scripts. Application and Next resolution paths report Sharp 0.35.5 and libvips 8.18.7.

This focused exception addresses published decoder advisories affecting untrusted image processing: [librsvg advisory, fixed in 0.35.5](https://github.com/lovell/sharp/security/advisories/GHSA-wq5f-xc86-pv6w), [libheif advisory, fixed in 0.35.4](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c), and [libvips advisory, fixed in 0.35.0](https://github.com/lovell/sharp/security/advisories/GHSA-f88m-g3jw-g9cj). Public primary-source review also checked the retained [Next 16.3.8 security release](https://github.com/vercel/next.js/releases/tag/v16.3.8), the [Next image advisory fixed in 16.3.6](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j), and [React's RSC security follow-up](https://react.dev/blog/2025/12/11/denial-of-service-and-source-code-exposure-in-react-server-components). The React package version alone does not describe Next's vendored RSC implementation.

Automatic approval review rejected the proposed bulk `npm audit --omit=dev --json` request because it would transmit potentially private workspace dependency metadata. It was not retried or bypassed. The approved alternative was public advisory research and an explicit public-package installation with `--no-audit --no-fund --ignore-scripts`. This is a focused review, not a clean audit certificate for every transitive dependency. A complete dependency audit remains a release-environment check using an authorized metadata policy.

The bounded photo tests ran against the patched decoder. The development Turbopack browser run stalled on image loads after changing mobile emulation; webpack development and production checks are recorded separately. No hosting/runtime configuration was changed remotely.
